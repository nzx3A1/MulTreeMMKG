# 科研文献综述

## 核心原则

- 将可验证来源置于行文流畅之前。每项事实性结论都要能回到论文、官方出版页、DOI 或可定位的本地 PDF 页码。
- 不根据标题、搜索摘要或二手综述虚构方法细节、实验数值和作者结论。
- 明确区分全文证据、摘要证据、元数据和推断；证据不足时保留空值并说明缺口。
- 检索当前文献时使用网络检索，并优先论文原文、出版社页面、作者预印本和权威学术数据库。
- 涉及项目论文时，先检查 `data/pdf/`、`data/raw_pdf/` 和已有 MinerU 解析结果，避免重复下载或重复解析。

## 工作流

1. 定义研究问题、时间范围、语言范围、文献类型和纳入排除标准。信息不完整但不影响方向时，采用合理默认值并显式记录。
2. 生成概念组及其同义词、缩写、中英文表达，再组合出可复现的布尔检索式。
3. 至少使用两个互补来源检索。计算机科学优先 OpenAlex、Crossref、Semantic Scholar、arXiv、DBLP 和出版社；中文研究可补充用户可访问的中文数据库。
4. 保存数据库名称、完整检索式、检索日期、结果数量和筛选理由。详细字段见 [research-protocol.md](references/research-protocol.md)。
5. 先按规范化 DOI 去重，再按标题、年份和第一作者识别无 DOI 的重复记录。预印本与正式出版版合并时保留版本关系。
6. 先进行标题与摘要筛选，再进行全文筛选；对每篇排除文献记录一个主要理由。
7. 精读时提取研究问题、方法、数据集、模态、基线、指标、主要结果、局限性及与本项目的关系。使用 [literature-matrix.csv](assets/literature-matrix.csv) 作为默认字段模板。
8. 按主题、技术路线或时间演进综合证据，不按论文逐篇堆砌摘要。指出共识、冲突、证据强弱和可验证的研究空白。
9. 交付前执行证据审计：检查 DOI/URL、年份、作者、引用与结论映射、数字来源以及“仅摘要”标记。

## 输出约定

根据任务规模交付以下部分中的必要项：

- 检索协议：研究问题、数据源、检索式、时间范围、检索日期和筛选标准。
- 文献清单：标准化题名、作者、年份、来源、DOI、URL、版本及访问状态。
- 文献矩阵：方法、数据、指标、结果、局限性、证据级别和项目关联。
- 综合综述：主题化叙述、对比结论、研究空白及后续检索建议。
- 审计说明：未获取全文、元数据冲突、待核验数字以及工具访问边界。

默认把结构化产物放到项目的 `output/literature_review/`；除非用户指定其他路径。不要覆盖已有文件，使用清晰的主题或日期后缀。

## 本项目适配

- 将“多模态知识图谱”“文档层次树”“图文表联合抽取”“模式约束实体关系抽取”“地学/油气知识图谱”作为常用概念组，但必须根据用户的具体研究问题调整。
- 比较抽取方法时分别记录文本、图像、表格三种模态路径，不把某一模态的结果泛化到整个系统。
- 引用本地解析内容时优先定位到原始 PDF 页码；解析 JSON 或 Markdown 只作为定位辅助，不替代原文证据。

## 资源路由

- 设计检索、筛选、去重或证据分级时，读取 [research-protocol.md](references/research-protocol.md)。
- 创建 CSV/XLSX 文献矩阵时，以 [literature-matrix.csv](assets/literature-matrix.csv) 为字段基础，可按研究问题增列但不要删除溯源字段。
- 处理 PDF 时同时使用已安装的 `pdf` skill；生成 Excel 时同时使用 `spreadsheets` skill；撰写 DOCX 时同时使用 `documents` skill。
