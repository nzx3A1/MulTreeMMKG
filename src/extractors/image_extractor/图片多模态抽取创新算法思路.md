# 图片多模态抽取创新算法思路

## 1. 设计目标

当前图片抽取流程已经能够调用 VLM/LLM 完成图片分类、图片描述和三元组抽取，但从论文创新性角度看，容易被评价为“直接调用大模型”。因此新的设计目标是：仍然采用基于大模型的技术路线，但把简单调用升级为一套可描述、可复现、可消融实验验证的多模态抽取算法。

本方案不使用 OpenCV 或传统图像处理算法，而是通过以下机制体现创新：

- 领域本体约束：用石油地质关系模板约束模型输出。
- 多轮视觉问答：让 VLM 按类型分解观察任务，而不是一次性生成答案。
- 证据链推理：所有实体和关系必须绑定图像证据、图题证据或正文证据。
- 图文双向验证：视觉实体与文本实体互相检索、互相确认。
- 自一致性投票：多个视角、多次推理结果融合，降低偶然幻觉。
- 候选关系校验：LLM/VLM 不自由生成全部三元组，而是先生成候选，再进行验证和排序。

建议算法名称：

**GeoVLM-ECA：面向石油地质图像的证据链增强视觉语言知识抽取算法**

其中：

- Geo：石油地质领域。
- VLM：视觉语言大模型。
- ECA：Evidence-chain Alignment，证据链对齐。

## 2. 与现有代码的兼容关系

现有入口不变：

```text
ImageModalProcessor.process_image(image_paths, caption, references, context)
```

现有输出不变：

```json
{
  "image_paths": [],
  "classification": {},
  "description": {},
  "extraction": {
    "triples": []
  }
}
```

最终仍由 `C2Imageinjector.py` 转成原来的图谱格式：

```json
{
  "chunk": {},
  "entities": [],
  "relations": []
}
```

因此，该算法是对 `ImageModalProcessor.py` 内部抽取策略的增强，不破坏当前项目已有的落盘格式和图谱写入逻辑。

## 3. 总体流程

原流程：

```text
图片 -> VLM分类 -> VLM描述 -> LLM三元组抽取 -> 原格式输出
```

新流程：

```text
图片 + 图题 + 引用文本
    -> 领域本体初始化
    -> VLM 多视角类型判别
    -> LLM 生成类型化视觉问题
    -> VLM 逐问题回答并生成证据链
    -> LLM 抽取视觉实体与文本实体
    -> 图文双向对齐
    -> 候选三元组生成
    -> VLM/LLM 交叉验证与自一致性评分
    -> 原格式输出
```

核心变化是：VLM 不再一次性“看图说三元组”，而是在领域本体和问题链引导下，分步骤回答可验证问题，再由 LLM 根据证据链构造和验证知识。

## 4. 核心算法

### 4.1 领域本体约束矩阵

先定义石油地质图片抽取中允许出现的实体类型和关系类型。该矩阵不是具体图像处理，而是领域知识约束。

实体类型示例：

| 类型 | 含义 |
|---|---|
| Stratum | 地层、层位 |
| Lithology | 岩性 |
| Reservoir | 储层 |
| SourceRock | 烃源岩 |
| Fault | 断层 |
| Structure | 构造单元 |
| Facies | 沉积相 |
| Curve | 曲线 |
| Axis | 坐标轴 |
| Parameter | 地质或实验参数 |
| Trend | 趋势 |
| Process | 地质过程 |
| EvidenceRegion | 图像证据区域或图像证据片段 |

关系模板示例：

| head 类型 | tail 类型 | 允许关系 |
|---|---|---|
| Stratum | Lithology | has_lithology |
| Stratum | Reservoir | contains |
| Structure | Fault | contains / controlled_by |
| Fault | Reservoir | controls |
| Curve | Parameter | quantifies |
| Curve | Trend | has_trend |
| Parameter | Parameter | increases_with / decreases_with |
| Process | Process | precedes / causes |
| Hydrocarbon | Fault | migrates_along |
| Hydrocarbon | Reservoir | accumulates_in |

抽取时，模型输出的关系必须能映射到模板中，否则进入低置信或剔除。

### 4.2 多视角 VLM 类型判别

图片类型不只问一次，而是让 VLM 从多个视角判断：

- 视觉结构视角：图片主要由曲线、剖面、地图、照片还是箭头流程组成。
- 地质语义视角：图片表达的是岩性、构造、储层、过程还是参数变化。
- 信息抽取视角：该图片最适合抽取趋势、空间关系、组成关系还是过程关系。

得到三个判断结果后进行一致性融合：

```text
Type_final = Vote(Type_structure, Type_semantic, Type_extraction)
```

若三个视角不一致，则进入“冲突解释”提示，让 LLM 给出最终类型和原因。

这比单次分类更稳定，也能作为论文中的算法模块。

### 4.3 类型化视觉问题生成

根据图片类型、图题、引用文本和领域本体，由 LLM 自动生成一组必须回答的视觉问题，记为：

```text
Q = {q1, q2, ..., qn}
```

不同图片类型的问题模板不同。

曲线图问题：

- 图中有哪些坐标轴？变量名和单位是什么？
- 图中有哪些曲线或图例？
- 曲线整体呈上升、下降、波动还是分段变化？
- 是否存在峰值、低值、拐点或异常段？
- 图题或正文中提到的实体是否能在图中找到视觉证据？

地质图/剖面图问题：

- 图中出现哪些地层、岩性、构造单元或井位？
- 不同地质对象之间存在包含、邻接、上下层位或切割关系吗？
- 图例、颜色、标注分别对应哪些地质含义？
- 图题或正文中的层位、岩性、构造名称是否被图像支持？

岩心/薄片图问题：

- 图中可见哪些岩性、矿物、孔隙、裂缝或纹理？
- 这些现象说明了什么储层特征或成岩作用？
- 是否有尺度、放大倍数或样品层位信息？

示意图问题：

- 图中有哪些地质要素？
- 箭头或流程表达了什么迁移、沉积、成藏或演化关系？
- 哪些过程先发生，哪些过程后发生？
- 哪些因素控制了油气聚集或储层发育？

这一阶段的创新点是：把图片抽取转化为“领域问题驱动的多轮视觉问答”，避免一次性描述遗漏关键信息。

### 4.4 视觉证据链生成

VLM 对每个问题输出结构化回答，而不是自然语言长段落。

单个回答结构：

```json
{
  "question": "图中有哪些岩性？",
  "answer": "图中显示砂岩和泥岩互层。",
  "visual_evidence": "右侧标注包含砂岩、泥岩，剖面中不同颜色层段交替出现。",
  "text_support": "references 中提到岩性主要为砂岩和泥岩互层。",
  "related_entities": [
    {"name": "砂岩", "type": "Lithology"},
    {"name": "泥岩", "type": "Lithology"},
    {"name": "沙四段地层", "type": "Stratum"}
  ],
  "confidence": 0.86
}
```

多个回答组合成证据链：

```text
E = {e1, e2, ..., en}
```

后续实体和关系只能从证据链中抽取，不能凭空生成。

### 4.5 视觉实体与文本实体联合抽取

LLM 分别从两个来源抽实体：

```text
V_entities = Extract(EvidenceChain)
T_entities = Extract(Caption + References + Context)
```

视觉实体来自证据链，文本实体来自图题、引用和上下文。

视觉实体格式：

```json
{
  "name": "砂岩层",
  "type": "Lithology",
  "attributes": {
    "visual_form": "层状分布",
    "occurrence": "与泥岩交替出现"
  },
  "evidence_span": "剖面中砂岩与泥岩层段交替出现",
  "confidence": 0.86,
  "source_modality": "figure"
}
```

文本实体格式：

```json
{
  "name": "沙四段地层",
  "type": "Stratum",
  "evidence_span": "XX油田沙四段地层，岩性主要为砂岩和泥岩互层",
  "source_modality": "text"
}
```

### 4.6 图文双向对齐算法

对视觉实体和文本实体进行双向匹配。

对齐分数：

```text
Align(v, t) = w1 * NameSim(v, t)
            + w2 * TypeSim(v, t)
            + w3 * ContextSim(v, t)
            + w4 * EvidenceSupport(v, t)
            + w5 * VLMJudge(v, t)
```

含义：

- `NameSim`：名称、别名、同义词相似度。
- `TypeSim`：实体类型是否一致。
- `ContextSim`：是否同处同一图题、章节或引用上下文。
- `EvidenceSupport`：视觉证据链是否支持该文本实体。
- `VLMJudge`：VLM 对“图中是否支持该文本实体”的判断。

双向约束：

```text
v -> t: 视觉实体选择最匹配文本实体
t -> v: 文本实体选择最匹配视觉实体
```

只有满足以下任一条件才建立对齐：

```text
MutualTop1(v, t) = True
或 Align(v, t) >= threshold_align
```

对齐结果不改变最终输出格式，而是进入：

- `evidence_span`
- `confidence`
- `source_modality`
- `relation_type = supports / aligns_with`

### 4.7 候选三元组生成

候选三元组不是让模型完全自由生成，而是由“证据链 + 领域模板 + 对齐结果”共同生成。

候选生成公式：

```text
C = GenerateTriples(E, OntologyRules, Alignments)
```

候选三元组格式：

```json
{
  "head": "沙四段地层",
  "relation": "主要岩性",
  "relation_type": "has_lithology",
  "tail": "砂岩和泥岩互层",
  "evidence_span": "图中砂岩和泥岩层段交替出现，references 中也提到岩性主要为砂岩和泥岩互层",
  "confidence": 0.88,
  "source_modality": "figure"
}
```

候选三元组必须满足：

- head 或 tail 至少一个来自视觉实体。
- relation_type 必须在领域关系模板中。
- evidence_span 必须来自视觉证据链、图题或正文引用。
- 置信度由多项分数融合得到。

### 4.8 LLM/VLM 交叉验证

对候选三元组进行两类验证。

LLM 验证：

```text
给定图题、references、证据链和候选三元组，判断该关系是否符合石油地质知识逻辑。
```

VLM 验证：

```text
给定图片和候选三元组，判断图片是否能够支持该关系。
```

验证输出：

```json
{
  "triple": {},
  "llm_valid": true,
  "vlm_valid": true,
  "conflict_reason": "",
  "revised_triple": null,
  "score": 0.87
}
```

最终分数：

```text
Score = a * S_evidence
      + b * S_alignment
      + c * S_ontology
      + d * S_llm
      + e * S_vlm
      + f * S_consistency
```

其中：

- `S_evidence`：证据链是否明确。
- `S_alignment`：图文实体对齐是否可靠。
- `S_ontology`：是否符合领域本体模板。
- `S_llm`：LLM 领域逻辑验证得分。
- `S_vlm`：VLM 图像支持验证得分。
- `S_consistency`：多次推理结果是否一致。

### 4.9 自一致性投票

为了减少单次模型输出的不稳定性，对关键步骤采用多样化提示重复生成。

例如候选三元组生成运行三轮：

```text
Run1: 以视觉证据为主
Run2: 以图题和引用文本为主
Run3: 以领域本体关系模板为主
```

最终保留满足以下条件的三元组：

```text
出现次数 >= 2
或 Score >= high_threshold
```

如果三轮结论冲突，则进入冲突裁决提示：

```text
请基于图片、图题、references、证据链，判断哪一个三元组最可靠，并说明保留或删除原因。
```

这一部分可以作为论文中的“自一致性证据融合机制”。

## 5. 算法伪代码

```text
Input:
    Images I
    Caption C
    References R
    Context X

Output:
    result = {
        image_paths,
        classification,
        description,
        extraction: { triples }
    }

Algorithm GeoVLM-ECA:

1. O = LoadGeoOntologyRules()

2. T1 = VLM_Classify(I, view="visual_structure")
   T2 = VLM_Classify(I, view="geological_semantics")
   T3 = VLM_Classify(I, view="extraction_task")
   image_type = ConsistencyVote(T1, T2, T3)

3. Q = LLM_GenerateQuestions(
       image_type=image_type,
       caption=C,
       references=R,
       ontology=O
   )

4. E = []
   for q in Q:
       e = VLM_AnswerWithEvidence(
           image=I,
           question=q,
           caption=C,
           references=R
       )
       E.append(e)

5. V_entities = LLM_ExtractVisualEntities(E, ontology=O)
   T_entities = LLM_ExtractTextEntities(C + R + X, ontology=O)

6. A = BidirectionalAlign(
       visual_entities=V_entities,
       text_entities=T_entities,
       evidence_chain=E
   )

7. Cands = LLM_GenerateCandidateTriples(
       evidence_chain=E,
       alignments=A,
       ontology=O
   )

8. Verified = []
   for triple in Cands:
       s_llm = LLM_Verify(triple, E, O, C, R, X)
       s_vlm = VLM_Verify(triple, I, C, R)
       s = FuseScore(triple, s_llm, s_vlm, A, O)
       if s >= threshold:
           Verified.append(NormalizeTriple(triple, s))

9. return original_schema_result
```

## 7. 论文创新点写法

### 创新点一：领域问题驱动的多轮视觉语言抽取

可写为：

> 针对地质图像信息密集、单轮视觉描述易遗漏关键要素的问题，本文提出领域问题驱动的多轮 VLM 抽取策略。该策略根据图片类型、图题和领域本体自动生成类型化视觉问题，引导 VLM 分别识别坐标轴、曲线趋势、岩性层段、构造要素和地质过程，从而提升图片语义解析的完整性。

### 创新点二：证据链增强的三元组生成

可写为：

> 本文设计证据链增强的知识生成机制，要求每个视觉实体和关系三元组均关联到视觉证据、图题证据或正文引用证据，避免大模型直接生成无来源知识，提高多模态知识抽取的可解释性。

### 创新点三：图文双向对齐机制

可写为：

> 本文提出视觉实体到文本实体、文本实体到视觉实体的双向对齐机制，综合名称相似度、类型一致性、上下文一致性和 VLM 证据判断得分，实现图片信息与正文知识的细粒度关联。

### 创新点四：领域本体约束的关系验证

可写为：

> 为降低 VLM/LLM 自由生成关系带来的幻觉，本文引入石油地质领域本体约束矩阵，对实体类型组合和关系类型进行先验限制，并通过 LLM/VLM 交叉验证筛选最终三元组。

### 创新点五：自一致性证据融合

可写为：

> 本文设计多视角提示下的自一致性证据融合方法，从视觉结构、地质语义和抽取任务三个视角生成候选结论，并采用投票与置信度融合策略提高抽取结果稳定性。

## 8. 与“直接调用大模型”的区别

本方案仍然基于 LLM/VLM，但不是简单 API 调用，区别在于：

| 普通大模型调用 | GeoVLM-ECA |
|---|---|
| 一次输入图片，直接输出结果 | 多阶段问题生成、回答、对齐、验证 |
| 模型自由生成三元组 | 领域本体约束候选关系 |
| 描述和抽取混在一起 | 先证据链，后实体关系 |
| 缺少证据来源 | 每个实体和关系绑定 evidence_span |
| 单次输出不稳定 | 多视角自一致性投票 |
| 难以消融实验 | 可分别消融问题链、本体、对齐、验证模块 |

因此论文中可以强调：本文不是提出新的视觉底层算法，而是提出一种面向石油地质图像知识抽取的 **大模型推理组织算法** 和 **证据约束抽取框架**。

## 9. 推荐代码落地方式

建议新增以下模块：

```text
modalprocessor/image/
  GeoOntologyRules.py          # 石油地质实体类型与关系模板
  GeoQuestionPlanner.py        # 根据图片类型生成类型化视觉问题
  EvidenceChainBuilder.py      # 调用 VLM 逐问题生成证据链
  CrossModalAligner.py         # 视觉实体与文本实体双向对齐
  TripleVerifier.py            # LLM/VLM 候选三元组验证与评分
  GeoVlmEcaExtractor.py        # 总控算法
```

`ImageModalProcessor.py` 可改为：

```text
process_image(...)
    -> GeoVlmEcaExtractor.extract(...)
    -> 返回 classification / description / extraction
```

这样既能保留当前工程结构，又能让论文方法部分有清晰的算法模块。

## 10. 实验设计建议

对比方法：

1. **Direct-VLM**：图片 + prompt 直接输出三元组。
2. **Caption-RAG-VLM**：图片 + 图题 + references 输出三元组，即当前基础方案。
3. **GeoVLM-ECA w/o Ontology**：去掉领域本体约束。
4. **GeoVLM-ECA w/o Alignment**：去掉图文双向对齐。
5. **GeoVLM-ECA w/o Verification**：去掉 LLM/VLM 交叉验证。
6. **GeoVLM-ECA Full**：完整方法。

评价指标：
